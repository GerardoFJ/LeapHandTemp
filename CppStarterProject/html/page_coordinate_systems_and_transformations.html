Coordinate Systems and Transformations

A description of the conventions used in HaptX software.

Coordinate System Conventions

At HaptX we map X, Y, and Z to the cardinal directions forward, left, and up, respectively. This can be seen in Figure 1 below, alongside other domains' coordinate systems for reference.

By default, the HaptX SDK uses the HaptX coordinate system, but the Unreal plugin follows Unreal Engine's conventions, and the Unity plugin follows Unity's conventions.

Tracking Origin: MCP3

The knuckle at the base of the middle finger, formally known as the middle metacarpophalangeal joint or MCP3 for short, is the datum with respect to which we express fingertip positions. For example, mocap systems populate mocap frames with fingertip locations that are relative to MCP3. See Figure 2 for a visual depiction of MCP3 and Listing 1 for an example of how to make queries with respect to MCP3 in code.

Figure 2. The HaptX convention for the middle metacarpophalangeal joint (MCP3) tracking origin.

Locating Feature: Fingertips

We define the very end of each finger as the fingertip location. Mocap systems populate mocap frames with fingertip locations relative to MCP3. See Figure 3 for a visual depiction of a fingertip transform, Listing 1 for an example of how to make fingertip transform queries in code, and Listing 2 for an example of converting a fingertip transform to world space.

Figure 3. The HaptX convention for fingertip locating features.

Listing 1

// Listing 1. Querying a mocap frame for a fingertip transform.
#include <HaptxApi/mocap_frame.h>
#include <HaptxApi/names.h>
// Populated by mocap systems.
MocapFrame mocap_frame = ...
TransformContext fingertip_context;
// Fingertip transforms are reported relative to the third metacarpophalangeal
// joint (a.k.a. the knuckle at the base of middle finger, a.k.a. MCP3).
fingertip_context.parent = getName(getBodyPartJoint(RelativeDirection::RD_RIGHT,
Finger::F_MIDDLE,
FingerJoint::FJ_JOINT1));
// We're specifically targeting the right index fingertip.
fingertip_context.child = getFingertipName(RelativeDirection::RD_RIGHT,
Finger::F_INDEX);
// Attempt to get the desired transform from the mocap frame (it doesn't
// necessarily contain it).
auto transform_it = mocap_frame.transforms.find(fingertip_context);
if (transform_it != mocap_frame.transforms.end()) {
// If the transform is found we can proceed.
Transform mcp3_fingertip = transform_it->second;
// Additional logic...
}

// Listing 2. Converting a fingertip transform to world space; error-handling
// elided for clarity.
#include <HaptxApi/openvr_wrapper.h>
#include <HaptxApi/tracker_loader.h>
#include <HaptxApi/world_transform_calculator.h>
using namespace HaptxApi;
// Given an Airpack...
std::shared_ptr<Airpack> airpack = ...
// Get a MocapSystem; just getting the first one here, but real code would
// iterate over them.
const auto& mocap_system = airpack->getMocapSystems()->begin();
// Get the serial number; again, real code would iterate over this map.
auto trackers = TrackerLoader::getAssociatedTrackerSerialNumbers(
mocap_system->getSerialNumberAsString());
std::string tracker_index = trackers->begin().first;
std::string serial_number = trackers->begin().second;
// Get the tracker transform.
std::map<int, HaptxApi::Transform> tracker_transforms{};
tracker_transforms[tracker_index] = OpenvrWrapper::getTrackerTransform(
serial_number).value();
// Get the world transform of the tracker mounted to the peripheral, assuming
// there is one.
MocapFrame l_mocap_frame;
mocap_system->addToMocapFrame(&l_mocap_frame);
Transform w_mcp3 = WorldTransformCalculator::calculateMcp3WorldTf(
mocap_system->getGlove(),
l_mocap_frame,
tracker_transforms).value();
// Acquired as in the previous example.
Transform mcp3_fingertip = ...
// Now we have everything we need to compute the world position of the
// fingertip.
Transform w_fingertip = w_mcp3 * mcp3_fingertip;

Tactor

We define a coordinate system for circular and elliptical tactors in which the X-axis aligns with the tactor's major axis, the Y-axis aligns with the tactor's minor axis, and the Z-axis is the axis of inflation (Figure 4). The orientation of major and minor axes is arbitrary for circular tactors, so long as they are perpendicular with the Z-axis.

The origin is the surface of the uninflated membrane at the center of the bubble. Transforms for tactors on the fingers are commonly expressed relative to fingertip locations. Transforms for tactors on the palm are commonly expressed relative to MCP3.

Figure 4. The HaptX convention for locating tactors.

Magnetic motion tracking ("mocap")

Finger tracking in HaptX Gloves G1 is performed using magnetic sensors. MocapSystem::addToMocapFrame automatically converts raw sensor data into fingertip position data for convenient consumption. For the benefit of power users, raw sensor data describing sensor placement relative to the Glove's magnetic emitter are also included in the resulting MocapFrame object.

  • The placement of each sensor relative to its nearby fingertip is described within MocapReceiver objects on a Peripheral .
  • Similarly, the placement of each magnetic emitter relative to MCP3 is described within each MocapTransmitter object of a Peripheral .
