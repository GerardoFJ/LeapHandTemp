HaptX Dashboard

The HaptX Dashboard is a tool that helps you interact with HaptX devices and applications. From within the Dashboard, you can adjust settings, view the actuation status of your hardware, access log files, get links to support documentation, and find updates.

Running the Dashboard

The HaptX Dashboard must always be running to interact with the HaptX SDK.

  • When the SDK is installed, the Dashboard is configured to launch when you log in.
  • If it is ever stopped for any reason, the Dashboard will also automatically launch whenever an HaptX SDK client application is executed.
  • The Dashboard can also be launched manually, if desired by running %HAPTX_SDK_HOME%\Tools\HaptxDashboard.exe .

While running, the HaptX Dashboard will present an icon in the System Notification Area (the "system tray"). You can click on the tray icon at any time to restore the Dashboard window.

Note that the HaptX Dashboard is intended to be running all the time, or at least while you're interacting with the SDK. Simply closing the window (e.g., by pressing the 'X' in the upper right corner of the window) will only minimize the Dashboard to the system tray.

If you want to completely terminate the Dashboard process, you can:

  • Invoke File → Exit from the menu (Ctrl +Shift +W ); or
  • Right click on the HaptX Dashboard icon in the system tray and choose Exit .

First-time setup

The first time the HaptX Dashboard runs, you will be prompted to agree to the End User License Agreement (EULA) and presented with instructions for pairing hand trackers with your gloves.

If you need to review the pairing instructions at a later date, they're available on the HaptX Support website. You can also refer to the Controlling Tracker Pairings section, below.

Log Windows

The HaptX Dashboard and each HaptX SDK client application create log files that contain diagnostic messages about their functionality. The HaptX Dashboard's log will mostly contain information about hardware connectivity, while the logs generated by SDK client applications will contain information about the operation of the higher-level functionality of the SDK, and the Unreal/Unity plugins.

These logs can be accessed via the HaptX Dashboard:

  • You can open the log directory with the File → Open Log Directory menu item.
  • You can also access individual log files with the File → Open Log File menu item.

The Dashboard can also be used to monitor log messages in real-time, which is invaluable for debugging problems as they occur:

  • The log file for the HaptX Dashboard itself can be displayed with the View → Debug Log → Show Debug Log setting, and cleared with View → Debug Log → Clear Debug Log .
  • Logs for HaptX SDK client applications can be displayed by enabling the View → Show external application output setting. If enabled, a new tab will appear for each SDK client application that is run; the tab name for each external application is identified by its executable name and process identifier (PID).

A dot next to the tab label indicates that new, unread messages are present.

The granularity of the information displayed in log windows is controllable through the View → Debug Log and View → External Applications menus, but note that these settings are not retroactive. If you're experiencing a problem, you may wish to set this to the lowest setting (DEBUG) before replicating the issue you're seeing. Otherwise, leave this set to a higher value to avoid unnecessary noise in the log files.

Hardware Visualizer

The HaptX Dashboard comes with a Hardware Visualizer that displays live haptic actuation information for physical or simulated gloves. To use this, ensure that the Hardware Visualizer is enabled under View → Hardware Visualizer → Show Hardware Visualizer .

With a glove attached (physical or simulated ), the Hardware Visualizer will render micro-fluidic actuators (tactors) as circles and force-feedback actuators as squares.

Elements are grouped by common locating feature, and each shape contains an ID number and a pressure in hectopascals (hPa). You can control the ID type that is displayed with the View → Hardware Visualizer → Display... menu items.

The color within each shape will transition from white to slate-grey (with a physical Airpack) or green (with a simulated Airpack) as the pressure corresponding to each element increases to the element's maximum pressure. Use the location and intensity of color on the display to gauge the overall distribution of haptic feedback.

Settings

Figure 3. Dashboard Settings Window

There are several settings available under View → Settings .

Session Timeout

Typically, the Airpack will enter a low-power idle mode when an application powered by the HaptX SDK finishes running.

This setting configures an extra timer to return the Airpack to its idle state after some time has elapsed without a new command, which might happen if the program gets stuck.

  • By default, the setting is 0, meaning the timeout is never applied. Set a different number to trigger the timeout after a certain amount of time (in seconds).
  • Note that your session should automatically terminate if the process communicating with the SDK exits, so you generally shouldn't need to set a value here except in exceptional circumstances.

You can also manually terminate a session's connection to the HaptX SDK via the Device → Terminate Session menu item.

Wireless Setup

You can configure the IP that the Dashboard uses to communicate with the HaptX Airpack here.

Note
Changing the IP Address setting does not make any changes to the Airpack; it is solely used as the address by which the Dashboard connects to the Airpack. You should modify this setting only if your DHCP server assigned a different IP address than the last time you ran the Wireless Setup wizard. For other changes, please run the Wireless Setup wizard directly.

You can also click the Setup Wizard button to launch Wireless Setup wizard .

Export/Import Settings

The Dashboard allows you to export your settings (which include these settings as well as things like window size and your wireless settings) to be imported on another computer. To use this functionality, simply press Export Settings , which will prompt you to save your settings to a file. Then, on another computer with the HaptX Dashboard, simply press Import Settings and load that file in.

Controlling Tracker Pairings

Figure 4. Dashboard Tracker Pairing Window

You can edit and view your current hand tracker pairings under View → Edit/View Tracker Pairings , which launches the Tracker Pairing window.

This window contains basic instructions, but more detailed instructions can be found on the HaptX Customer Support website.

To add a new pairing, simply press the Add button and manually input the serial number of the tracker you're trying to pair, then press Save . You can also remove and edit existing pairings through this window.

A yellow-shaded cell indicates modifications that will be written out when you press Save .

Using physical and simulated hardware

In addition to facilitating communication with physical hardware, the Dashboard can also be used to simulate an Airpack (while still using physical HaptX Gloves for motion capture), or to simulate the complete HaptX Gloves G1 system (Airpack and Gloves).

Using physical hardware

If the Device → No Simulation setting is checked in the menu, the Dashboard will attempt to connect to a physical HaptX Gloves G1 system.

If your Airpack is powered on, and the Airpack's USB cable is connected to your workstation, the Dashboard will initiate a connection to the Airpack. The Airpack status icon will indicate the current connection status:

Status Icon Status
uncolored 		Airpack connection has not been attempted
Green 		Airpack successfully connected
Yellow 		Airpack reported a recoverable / soft fault error-condition
Red 		Airpack connection failed; or Airpack reported a hard fault error-condition
Note
HaptX Gloves G1 also supports communication with the Airpack over Wi-Fi. See below for details.

The Dashboard next attempts to connect to gloves connected to the Airpack. The Gloves status icon will report indicate the current connection status of the gloves:

Status Icon Status
uncolored 		Glove connection has not been attempted
Green 		Two gloves successfully detected
Yellow 		Only one glove detected; or both are right- or both left-handed
Red 		No gloves detected

If the Hardware Visualizer is visible, attached gloves will be displayed as soon as they are detected.

If both the Airpack and Gloves status icons are green, you are ready to run your HaptX SDK client application.

The Dashboard listens for USB hot-plug events, and will re-attempt hardware detection whenever a HaptX Airpack or a HaptX Glove are connected or disconnected. Note that it can take as long as 15-20 seconds for hardware to be detected after a hot-plug event.

Warning
Don't plug or unplug the USB cables for either the Airpack or gloves while a HaptX SDK client application is running. The hardware connection takes time to be reestablished, and the active session will fail.

Using simulated hardware

The HaptX Dashboard also has the ability to simulate parts of the HaptX Gloves G1 system.

If the Device → Simulate Airpack menu item is selected, the Dashboard will simulate an Airpack, while still allowing you to use physical HaptX Gloves for motion-capture. In this mode:

  • The Dashboard will not attempt to connect to a physical Airpack, even if one is present.
  • The Airpack status icon will remain uncolored.
  • The Gloves status icon will behave as described in the section on using physical hardware.
  • HaptX Gloves may be attached to a powered-on Airpack that is connected to your workstation. Note that the gloves have non-standard power requirements, so direct USB connections to your computer workstation are not supported.
  • The Hardware Visualizer will render pressure setpoints in green (instead of slate-grey) as a visual indication that the Airpack is simulated (and therefore no pressure is actually being sent to the gloves).
Note
Wi-Fi connections to HaptX Gloves are not supported in the Simulate Airpack mode.

The Dashboard can also simulate the complete HaptX Gloves G1 system—both Airpack and Gloves—by selecting the Device → Simulate Airpack and Gloves menu item. In this mode:

  • The Dashboard will not attempt to connect to a physical Airpack or physical gloves, even if present.
  • Both Airpack and Gloves status icons will remain uncolored.
  • The Hardware Visualizer will render pressure setpoints in green (as above), and any loaded gloves will be labeled with a SIMULATED suffix.

When you run a HaptX SDK client application in this mode, the Hardware Visualizer will automatically be populated with two default gloves, and the SDK will report those gloves to the client application. If you prefer a different configuration, you can load individual glove definitions with the View → Hardware Visualizer → Load simulated glove menu item, and reset them with the View → Hardware Visualizer → Clear simulated gloves menu item.

Connecting a HaptX Airpack to Wi-Fi

Figure 5. Wireless Setup Wizard

In addition to USB, the HaptX Airpack is able to connect via a Wi-Fi network.

Wireless functionality on the Airpack can be configured through the HaptX Dashboard. The Wireless Setup wizard is launched by the Devices → Wireless Setup menu item.

Note
You must be connected via the USB cable when you configure the Airpack's wireless parameters.

The wizard will prompt you for Wi-Fi network credentials. The HaptX Dashboard does not store the password on your workstation; it is used only to allow the HaptX Airpack to connect to the Wi-Fi router. (If you do not enter a password, the Airpack will keep using a previously-specified password.)

You'll also be given the choice of using DHCP or a static IP when connecting. If you're unsure, just leave Use DHCP selected. However, unless you configure a static IP or your DHCP server reserves a fixed IP for the Airpack, you may have difficulty using the wireless capability if the assigned IP address of the Airpack changes in the future. Don't worry if you don't know what any of this means—just run the Wireless Setup wizard again if you run into any problems.

After entering your information, the Airpack will attempt to connect to the Wi-Fi network using the credentials you supplied. Once connected, you can complete the wizard, and then you'll be able to use your HaptX Gloves G1 wirelessly!

Note
It takes slightly longer to detect glove hot-plug events when using a Wi-Fi connection—as long as 20-25 seconds after a new glove is connected to the Airpack. Please allow adequate time to elapse if swapping the attached gloves, and monitor the Gloves status icon and the Hardware Visualizer display for confirmation of a successful connection.

If you want to go back to using the USB connection, just plug the USB cable in. The system will automatically connect through USB if the cable is detected, and through Wi-Fi otherwise.

Notes for network administrators

The HaptX Airpack and the computer workstation must be on the same network for proper wireless functionality.

The HaptX Dashboard attempts to reach the Airpack via the IP address specified in the Settings dialog . This connection must be possible:

  • The HaptX Airpack listens and responds to ICMP ("ping") traffic; if a firewall is used, ICMP traffic must be allowed.
  • The HaptX Airpack listens for incoming TCP connections on port 31337; if a firewall is used, this port must be opened for TCP traffic.

The HaptX Airpack does not make outbound network connections.

For the best results, HaptX recommends a wired connection between the computer workstation and the Wi-Fi network router that the Airpack is configured to use. Other network configurations are possible, but might result in higher latency. In general, the fewer 'hops' between the workstation and Airpack, the better.

Updating device firmware

Figure 6. Firmware Update Wizard

The HaptX Dashboard can be used to update the firmware on your HaptX Gloves G1. The Firmware Update wizard is launched by the Devices → Update Firmware menu item.

When the wizard first launches, you'll be prompted to choose whether to update the firmware on your HaptX Airpack, or on the HaptX Gloves. Next, you'll be prompted to connect your devices and power them on.

Note
You must be connected via the USB cable in order to update device firmware. If updating firmware on the gloves, they must be connected to the USB ports on a running Airpack, which must be connected via USB.

Next, you are prompted to select the firmware version to update to. The HaptX SDK comes with firmware versions that have been tested with the SDK and released concurrently. However, HaptX Support may occasionally supply updated firmware outside of a regular SDK release, so the Firmware Update wizard also allows manual selection of a firmware file to use.

Note
Unless advised otherwise by HaptX Support, you are encouraged to update to the bundled firmware versions of the firmware at a minimum—or use any newer versions available on the HaptX Support website—with this SDK release.

After selecting the firmware version to use, the wizard will start updating your device(s). This process can take several minutes.

Warning
Do not disconnect or power-off your devices during the firmware update process. If the update is interrupted, your device may be left in an unusable state. If this happens, device functionality can be restored by running the Firmware Update wizard again.

When the process is complete, your devices are ready to use.

Interacting with other HaptX applications

The HaptX dashboard can also launch other HaptX applications. If you need to use the User Profile Utility or the Mocap Visualizer, both are available to launch under the File → Launch Application menu.

Note
The Mocap Visualizer can only be launched when you are simulating both gloves and Airpack. Change your simulate state from the toolbar before launching it, and remember to change it back when you're done if you want to use physical hardware after.

Support data

In addition to the text-based log files, the HaptX Dashboard will collect some structured data to assist in any customer support interactions.

The data is stored in an database file called SupportData.db, which can be found in the same directory as the log files, and accessed with the File → Open Log Directory menu item.

The database is encrypted at rest, but the entire contents can be viewed directly in the Dashboard with the View → Collected Data menu item.

Getting support

In addition to the customer support website, there is some help available through the Dashboard itself. You can find a link to this and the rest of our documentation under Help → Documentation . There is also a link to check for SDK and firmware updates under Help → Get Updates . Lastly, you can find contact information and license information under Help → About .
