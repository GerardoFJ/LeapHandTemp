Detailed Description

Recommends hardware actuation patterns given information about the state of a virtual environment.

The contact interpreter requires knowledge of microfluidic actuators (tactors) and the virtual environment in order to function. This happens through a "registration" paradigm. To communicate information about a tactor, simulated object, or haptically enabled body, call an appropriate "register" function. (For example, to make the contact interpreter aware of a tactor, use registerTactor().) These registration functions also provide an opportunity to customize the behavior of the registered element. Registering an element a second or subsequent time will update its assigned properties.

Generally, it's a good idea to register all tactors , "force-feedback actuators" , and haptically enabled bodies at the start of the application alongside known objects. Objects that later come into existence should be registered as soon as possible after they appear.

The state of the virtual environment is communicated to the contact interpreter using "samples" and "contacts." A sample describes the distance between a haptically-enabled body and a nearby object; a contact describes information about a collision between a body and an object.

Samples are effectively linked to a Tactor and factor into the calculation of the hardware element's ideal inflation height. Each simulation frame, call addSampleResult() for every ray trace cast from a haptically enabled body.

Contacts determine the response of ForceActuators and also contribute to target tactor inflation heights. Call addContact() for every contact between an object and a haptically enabled body.

After all sample results and contacts have been shared with the contact interpreter, call commit() to produce a collection of HapticFrames containing actuation information for elements on each peripheral.

◆ addContact()

bool HaptxApi::ContactInterpreter::addContact ( ObjectId object_id,
BodyId body_id,
const Vector3D & w_impulse_ns = Vector3D::zero() )

Shares info about a recent contact.

Call this for every contact between a haptically enabled body and another object every frame.

If the contacting object isn't currently registered with the contact interpreter, this method registers this object and assigns it ContactInterpreter::DEFAULT_OBJECT_PARAMETERS (which can be updated by a subsequent call to registerObject()). Similarly, if the contacted body isn't currently registered with the contact interpreter, this method registers the body and assigns it ContactInterpreter::DEFAULT_BODY_PARAMETERS (which can be updated by a subsequent call to registerBody()).

Parameters
object_idThe ID of the object contacting the haptically enabled body.
body_idThe ID of the haptically enabled body being contacted.
w_impulse_nsThe world-space contact impulse imparted by the object on the haptically enabled body [N*s]. (In a free-body diagram, this is the impulse acting on the haptically enabled body in the world's coordinate system.)
Returns
True if the contact was successfully logged by the contact interpreter.

Shares info about the result of a ray trace.

Call this every frame for every haptic ray trace emerging from a haptically enabled body.

If the sampled object isn't currently registered with the contact interpreter, this method registers this object and assigns it ContactInterpreter::DEFAULT_OBJECT_PARAMETERS (which can be updated by a subsequent call to registerObject()). Similarly, if the sample's parent Tactor has been registered with a body but the body itself is not registered with the contact interpreter, this method registers the body and assigns it ContactInterpreter::DEFAULT_BODY_PARAMETERS (which can be updated by a subsequent call to registerBody()).

Precondition
A Tactor object whose ID matches the tactor_id argument must already be registered with the contact interpreter via registerTactor().
Parameters
peripheral_idThe ID of the peripheral containing the tactor this result affects.
tactor_idThe ID of the tactor this result affects.
w_trace_directionThe world-space direction of the ray trace.
object_idThe ID of the object struck by the ray trace.
distance_mThe distance between the surface of the body and the surface of the nearby object along the trace axis.
w_location_mThe world-space location of the trace hit [m].
w_normalThe world-space normal of the object surface at the trace hit.
uv_coordinatesUV coordinates of the trace hit.
Returns
True if the sample result was successfully logged by the contact interpreter.

Processes all reported sample results and contacts into a suitable actuation pattern for the microfluidic actuators (tactors).

This variant of commit() uses an explicit time delta for filtering and integrating. This is useful for tests or other situations in which the time between calls to commit() does not accurately reflect the time elapsed between changes to the simulation.

Returns

◆ getCompressionFilterAttackRatio()

float HaptxApi::ContactInterpreter::getCompressionFilterAttackRatio ( ) const

Get the ratio that we decrease the current compression filter scale by when a haptic signal containing effect output doesn't fit entirely within the max inflation for a tactor.

Should always be between 0 and 1 (inclusive). A value of 1 disables attacking; small values mean an aggressive attack; 0 means a perfect/infinite attack rate, and you'll never see signal output above max inflation.

Returns
The value of the parameter described above.
