Unreal Troubleshooting

Troubleshooting guide for the HaptX Unreal Plugin.

If you're having a problem not mentioned here, or if you have one of these problems but none of the listed solutions help you, please contact HaptX Support at suppo.nosp@m.rt@h.nosp@m.aptx..nosp@m.com.

Avatar hands are missing, or disappear once game starts

Make sure your VR controllers/trackers are on and being tracked by SteamVR. If they are on but not being tracked, ensure they are within view of the lighthouse base stations. If that doesn't resolve the problem, try restarting SteamVR, re-pairing the trackers in SteamVR, and restarting the game engine.

One or more visualizers don't turn on

If you're trying to toggle a visualizer using input hotkeys, try finding the relevant property on your HaptxHand Blueprint or HaptxCore Blueprint and toggling it manually instead. If that works, you may not have your project's input settings configured correctly. See the Unreal Integration Guide for instructions on how to configure these input settings.

Keywords: trace, tactile feedback, force feedback, grasp, mocap, motion capture

The trace visualizer doesn't sense objects or doesn't work as expected

On your HaptxCore Blueprint, check to make sure the Tactile Feedback Collision Types property includes the collision type of the object you're trying to feel.

Make sure the object you're trying to feel has collision geometry that is accurate to its visual mesh.

If traces are hitting objects, but all hit locations are red check to make sure that your HaptxHand Blueprint has a collision type of Pawn .

Note
Some trace hit locations may be red depending on hand size, but the majority of them should be teal in all cases.

Keywords: sample, ray, raycast, raytrace

I don't feel tactile feedback; or the tactile feedback visualizer doesn't sense objects

First turn on the Trace Visualizer, and make sure tracing is functioning correctly. If it is not, refer to Unreal Integration Guide for further guidance.

On your HaptxCore Blueprint, check to make sure the Enable Tactile Feedback property is true. Also check to make sure its Tactile Feedback Collision Types property contains the collision type of the object you're trying to feel.

Make sure that each UHxPatchComponent's Tactor Parameters properties and each AHxHandActor's Body Parameters properties are configured with values similar to their defaults.

Make sure that your object doesn't have a UHxPhysicalMaterial on it with the Disable Tactile Feedback property set to true.

I don't feel force feedback / the force feedback visualizer doesn't sense objects

On your HaptxCore Blueprint, check to make sure the Enable Force Feedback property is true. Also check to make sure its Force Feedback Collision Types property contains the collision type of the object you're trying to feel.

Make sure that your object doesn't have a UHxPhysicalMaterial on it with the Force Feedback Enabled property set to false.

If none of the above works, and you're interacting with objects that are physically welded together, there is a known issue that when you are contacting an object you will occasionally feel properties of other nearby, welded objects that you're not in contact with. This appears to be an issue with PhysX, or Unreal's implementation of PhysX.

It's difficult to pick up objects / grasping isn't working / the grasp visualizer doesn't sense objects

On your HaptxCore Blueprint, verify the following properties:

  • Enable Grasping is true
  • Grasp Collision Types contains the collision type of the object you're trying to grasp
  • Grasp Threshold property is not large
  • Grasp Friction is large
  • Grasp Friction Combine Mode is reasonable

See property documentation and defaults in editor for recommended values.

When using VR controllers to simulate gloves, be gentle when pulling the trigger to perform gestures. If you pull too hard you can generate extremely strong forces in game, which would cause objects to pop out of your grasp. This is less of a problem on HaptX hardware because the force feedback system stops your fingers from passing through solid objects.

Make sure that your object doesn't have a UHxPhysicalMaterial on it with the Grasping Enabled property set to false.

Keywords: grasp, grab, grip, pick up, slip, fall, drop, tight, loose

The hands or fingers crumple on objects if I press too hard

Like all physically simulated objects, the hand model may respond erratically to extreme forces. Attempting to push the virtual hand through solid objects or constrain it in an unusual manner may cause it to deform. This is expected behavior. There is nothing to prevent someone using the simulated motion capture system or the HaptX Gloves G1 hardware from pushing their controllers, hands, or fingers through a solid virtual object.

To mitigate this behavior you can try the following changes:

  • On your HaptxHand Blueprint the parameters related to Corrective Teleportation may be of interest.
  • On your HaptxHand Blueprint try lowering the Configuration → Linear Drive → Stiffness and/or Configuration → Linear Drive → Max Force parameters.
  • Navigate to haptx Content → HaptXHand in the content browser. In both physics assets, try increasing the Position Solver Iteration Count and Velocity Solver Iteration Count properties on each body of the skeletal meshes.

Keywords: crumple, crush, bend, break, broken, weird, finger, force, poke

I'm trying to disable a haptic feedback mode on an object with a UHxPhysicalMaterial, but it's still enabled

Make sure the UHxPhysicalMaterial is on the UPrimitiveComponent , not the UMaterial on the object. The Unreal Plugin does not currently support the latter.

There are certain properties of UHxPhysicalMaterials that can't be specified on weld-children; see here for more information.

Keywords: haptic material, tactile feedback, force feedback

Packaged build crashes on startup

This is an intermittent and inconsistent error that may occur depending on the version of Unreal Engine you are using. To fix it, uncheck Event Driven Loader Enabled in Project Settings and re-package your project. See this thread for more information.

Keywords: build, package, crash

I see three dashes (---) in properties of Haptic Primitive blueprint instances

We are aware of this issue, and the configuration you have in the blueprint may still function as expected despite this. If it does not, try changing the problematic parameters on the instance, then clicking the yellow 'revert' arrow to reset them to their default values.

I see errors or warnings appearing in the log that aren't visible on my HMD

It's possible that none of the errors or warnings you're seeing are considered actionable enough to appear in the on-screen log. Only user-critical errors are displayed on the HMD.

Verify that the Logging → Left Margin and Logging → Top Margin settings on your HaptxCore Blueprint are reasonable for your viewport size and that on-screen logging is enabled.

My fingers don't track right when the game starts

Connecting to motion tracking hardware requires approximately 1/8 second. During this brief period, hands will not appear and the game engine may hang.

I can't touch my fingers together in-game/I can't pick up small objects/my fingertips stick together in-game

The plugin uses compensation system in the hand animation module that accounts for the thickness of the HaptX Glove G1 fingertips when calculating the distance between your fingertips. If you're noticing that when you bring your actual fingertips together your fingertips in-game either have a gap between them or they tend to stick together like magnets, try adjusting AHxHandActor::thimble_compensation_parameters_.

My fingers are scrunched up/too straight when not in contact with anything

Try making a flat hand in game. This triggers an automatic correction that gradually adjusts the appearance of your fingers while they're held out straight. See AHxHandActor::glove_slip_compensation_parameters_.

I can't feel my Haptic Effect

Make sure that your effect is outputting nominal forces or displacements (see Haptic Effect Tuning).

Make sure that your effects aren't outputting negative values unless you intend to subtract from pre-existing inflation contributions.

Make sure that your effect is running (UHxHapticEffectComponent::start, UHxHapticEffectComponent::isRunning). Also make sure your effect has a reasonable duration (UHxHapticEffectComponent::setDurationS, UHxHapticEffectComponent::setLooping). It may be the case that the effect finishes too quickly to be felt.

If you are spawning a UHxObjectEffectComponent at runtime without an attached parent you need to call UHxObjectEffectComponent::addToObject manually.

My Haptic Effect is too intense

Make sure that the forces or displacements being generated by your effect are nominal (see Haptic Effect Tuning).

If you have multiple Haptic Effects operating on the same tactor their results will be summed.

I feel my Haptic Effect everywhere

If you are using a UHxSpatialEffectComponent with its bounding volume set to nullptr, this is expected behavior. Define a bounding volume if you want to control where this effect applies spatially.

UHxDirectEffectComponents are configured by default to apply to all tactors, but you can remove some if desired. See: UHxDirectEffectComponent::removeFromCoverageRegion, UHxDirectEffectComponent::removeFromTactor.

I always feel my Haptic Effect

Make sure your effect has a non-negative duration (UHxHapticEffectComponent::getDurationS, UHxHapticEffectComponent::setDurationS). All durations less than zero are treated as infinite.

Make sure your effect is not set to loop (UHxHapticEffectComponent::isLooping, UHxHapticEffectComponent::setLooping). If a Haptic Effect is set to loop, it will restart back to the beginning of its timeline whenever it has been running for longer than its duration.
