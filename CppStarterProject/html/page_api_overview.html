API Overview

An overview of our API.

Note

  • For Unreal projects, please consult the Unreal Integration Guide and Unreal Quick Start Guide.
  • For Unity projects, please consult the Unity Integration Guide and Unity Quick Start Guide.

Read on if you want to add haptic functionality to a custom application or create a plugin for a different engine.

Important stacks

The HaptX SDK has two major information pathways:

  • the mocap stack, which converts data from motion-capture receivers and world-space trackers (e.g., HTC VIVE Trackers ) into hand posture information used by the simulation; and
  • the haptics stack, which converts simulation information into haptic commands used by hardware.

These are shown in Figure 1.

Figure 1. Stacks within the HaptX SDK.

Mocap stack

As the fingers of a HaptX Glove G1 move, mocap systems generate mocap frames that may be passed to algorithms like DefaultHandIk to generate Anim Frames . The absolute position of the hand can be computed by multiplying the output value of OpenvrWrapper::getTrackerTransform and the inverse of the tracker's transform relative to the hand. The simulation takes this information, processes it with the WorldTransformCalculator , and adjusts the virtual hand accordingly.

Haptics stack

The simulation first sends contact data to the Grasp Detector and establishes grasps as the interface recommends.

It then sends similar contact data along with ray-trace information to the Contact Interpreter , which computes appropriate Haptic Frames . Any Haptic Effects in existence also get evaluated at this time.

Haptic frames then get converted to Pneumatic Frames via algorithms like DirectPneumaticCalculator and passed to Airpacks for rendering.

At this point, micro-fluidic actuators in the HaptX Gloves G1 (also known as tactile actuators, or simply tactors) engage. This allows the user to feel the associated haptic response, see corresponding changes in the virtual environment, and respond accordingly.

The process then begins anew from the mocap stack.

Module summary

The core competencies of the HaptX API are organized into modules (Table 1). The following section describes how to operate these modules in a typical application.

Module Function
Airpack The hardware interface for the pneumatic rendering of haptic set-points.
Animation Converts motion capture data into joint angles defining the pose of the human body.
Contact Interpreter Computes haptic response patterns given information about the state of a virtual environment.
Grasp Detector Recognizes grasps given information about the state of a virtual environment.
Haptic Effects May be extended to define custom haptic response patterns.
HaptX System The recommended entry point for applications using the HaptX API. Detects hardware interfaces and distributes handles to them.
Logging The logging interface for HaptX system messages.
Motion Capture Transform data for various locating features.
Peripheral The software representation of a HaptX peripheral / glove.
Transform Classes related to spatial translation, rotation, and scale.
Table 1. Primary HaptX API modules.

The typical HaptX-enabled simulation

All applications and plugins that operate the HaptX SDK must be set up, updated, and torn down properly. This section assumes use of the HaptX System , which helps detect and distribute handles to connected hardware. Not all of the following steps are needed for all applications.

Setup

Call these once at the beginning of the application:

  • Detect connected devices via HaptxSystem::detectDevices .
  • Initialize relevant hardware handles provided by the HaptxSystem:
    • HaptxSystem::getMocapSystems ; and
    • HaptxSystem::getAirpacks .
  • Retrieve the active user profile via UserProfileDatabase::getActiveUsername .
  • Get active Peripherals via Airpack::getAttachedPeripherals and register their tactors and force actuators with the ContactInterpreter:
    • ContactInterpreter::registerTactor ; and
    • ContactInterpreter::registerForceActuator .
      Note
      If you are using any Spatial Effects , make sure to associate SimulationCallbacks with Tactors as you register them.
  • Register all player-controllable bodies with the Grasp Detector and Contact Interpreter:
    • GraspDetector::registerBody ; and
    • ContactInterpreter::registerBody .
      Note
      If you are using any Object Effects , be sure to include SimulationCallbacks in the latter registration.
  • Register all known interactive objects with the Grasp Detector and Contact Interpreter:
    • GraspDetector::registerObject ; and
    • ContactInterpreter::registerObject .
      Note
      If you are using any Object Effects , be sure to include SimulationCallbacks in the latter registration.
  • If needed, instantiate and configure custom Haptic Effects.

Update

Perform these once each meaningful frame:

  • Compute the absolute positions of hands:
    • OpenvrWrapper::getTrackerTransform
  • Compute finger joint articulations:
    • MocapSystem::addToMocapFrame ; and
    • DefaultHandIk::addToAnimFrame .
  • Register new objects with the Grasp Detector and Contact Interpreter:
    • GraspDetector::registerObject ; and
    • ContactInterpreter::registerObject .
      Note
      If you are using any Object Effects , be sure to include SimulationCallbacks in the latter registration.
  • Communicate contacts to the Grasp Detector and the Contact Interpreter:
    • GraspDetector::addGraspContact ; and
    • ContactInterpreter::addContact .
  • Cast a ray trace from each Tactor located in the virtual space and report each result to the Contact Interpreter:
    • ContactInterpreter::addSampleResult
  • If needed, instantiate and configure custom Haptic Effects.
  • Prompt the Contact Interpreter to compute haptic frames:
    • ContactInterpreter::commit
  • Convert haptic frames to pneumatic frames:
    • DirectPneumaticCalculator::addToPneumaticFrame
  • Render the pneumatic frames on their associated Airpacks .
  • Prompt the Grasp Detector to compute grasps based on contact information provided since the last frame:
    • GraspDetector::detectGrasps
  • Pull grasp information from the Grasp Detector and perform simulation-specific actions as needed:
    • GraspDetector::getGraspHistory
  • Clear the grasp history:
    • GraspDetector::clearGraspHistory

Teardown

Perform these at the end of the simulation:

  • Shutdown all the hardware handles you initialized from HaptxSystem .

C++ starter project

The SDK comes with a functioning C++ starter project (CppStarterProject) that provides a working example of how to use the HaptX API. You have the option to extract this project when you run the SDK installer.

Software prerequisites

  • Microsoft Visual Studio 2019 with "Desktop development with C++" workload
  • OpenVR (commonly acquired through SteamVR), required for tracking HaptX Gloves in normal operation and handheld controllers in simulated motion capture mode
