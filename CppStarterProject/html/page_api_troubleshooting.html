API Troubleshooting

Covers specifically API-related issues. For plugin issues, consult Unity Troubleshooting or Unreal Troubleshooting.

We highly recommend using The typical HaptX-enabled simulation as a model for any custom application that employs the HaptX API.

Many error conditions are captured in the System Log. See System Logs for more information.

If this page doesn't solve your issue, email suppo.nosp@m.rt@h.nosp@m.aptx..nosp@m.com for assistance.

Motion capture: fingers appear "flipped" 180 degrees

  • In most cases, this can be resolved by restarting your application.
  • When beginning an application while not wearing HaptX Gloves G1, check that the fingers of the gloves are in neutral positions (closer to a flat hand rather than a fist) and that they are not folded, stretched, or crossed over one another.

Motion capture: return value is MOCAP_SOLVER_ERROR

  • This intermittent condition is typically innocuous and can be ignored.
  • Users may find this condition occurs more frequently when making a fist pose or when operating in an environment with higher-than-usual levels of magnetic interference.

Contact Interpreter: Tactors don't respond to addSampleResult() or addContact()

  • Make sure that ContactInterpreter::commit is called each frame after all sample results and contacts have been communicated.
  • Tactor s cannot be triggered using ContactInterpreter::addContact alone. Make sure the object participating in the contact is also referenced in ContactInterpreter::addSampleResult for all samples whose associated Tactor s you expect to inflate.
  • Make sure that tactile feedback is enabled. Though tactile feedback should be enabled by default, you can call setTactileFeedbackEnabled(true) to force the flag explicitly. Poll isTactileFeedbackEnabled to check the current flag state.
  • Confirm that the object and the haptically-enabled body involved in the interaction are registered with the interface (ContactInterpreter::registerObject , ContactInterpreter::registerBody ).
  • Check that all Tactor s are registered with the interface before ContactInterpreter::addSampleResult or ContactInterpreter::addContact is called (ContactInterpreter::registerTactor ).
  • Make sure the object is set to trigger tactile feedback (ContactInterpreter::ObjectParameters::triggers_tactile_feedback is true).
  • If the object is near but not touching the hand, make sure the sum of the ObjectParameters::base_contact_tolerance_m object parameter and the BodyParameters::base_contact_tolerance_m body parameter is greater than the distance provided in addSampleResult .
  • Make sure TactorParameters::dynamic_scaling and TactorParameters::max_height_target_m are strictly positive for all Tactor s in question.

Contact Interpreter: Force-feedback actuators don't respond to addContact()

  • Make sure that ContactInterpreter::commit is called each frame after all contacts have been communicated.
  • Make sure that force feedback is enabled. Though force feedback should be enabled by default, you can call setForceFeedbackEnabled(true) to force the flag explicitly. Poll isForceFeedbackEnabled to check the current flag state.
  • Confirm that the object causing the contact and the haptically-enabled body are registered with the interface (ContactInterpreter::registerObject , ContactInterpreter::registerBody ).
  • Check that all force-feedback actuators are registered with the interface before addContact is called (ContactInterpreter::registerForceActuator ).
  • Make sure the object is set to trigger force feedback (ObjectParameters::triggers_force_feedback is true).
  • Confirm that the w_impulse_ns argument of addContact points in a similar direction to at least one of the force-feedback actuator's restriction directions and that the dot product of the accumulated force and the restriction direction is greater than the force-feedback actuator's actuation threshold .
  • Check that ForceActuator::actuation_pressure_pa is strictly positive.
  • The Contact Interpreter applies a force filter for better force-feedback actuator disengagement behavior. If the force trends to a lower magnitude in successive calls to addContact , the force-feedback actuator may disengage even when there is a contact present. This is intended behavior.

Grasp Detector: grasps aren't forming

  • Make sure that GraspDetector::detectGrasps is called each frame after all grasp contacts have been added.
  • Confirm that all player-controlled bodies and the objects being contacted are registered with the interface (GraspDetector::registerBody , GraspDetector::registerObject ).
  • Check that the default grasp threshold isn't too large. Poll the value with getDefaultGraspThreshold or set a new value with GraspDetector::setDefaultGraspThreshold .
    • Values around 50 tend to work well.
  • Check that the can_be_grasped field of the ObjectParameters given to the object is set true.
  • If the object overrides the default grasp threshold via the override_default_grasp_threshold property of its associated ObjectParameters , make sure its grasp_threshold_n value is not too large.
    • Values around 50 tend to work well.

Airpack: return value is something other than SUCCESS

  • Please consult the ReturnCode documentation for more information.

No apparent response from the Airpack

  • Confirm that the Airpack has nominal colors on its status and power LEDs. Refer to the hardware-specific manuals for information about what various LED status colors mean.
  • Consult the System Logs for the presence of any errors and act on them.

I can't feel my Haptic Effect

  • Make sure that your effect is outputting nominal forces or displacements.
    • When working with default values, Haptic Effects that output forces of 100–250 N or displacements of about 0.75–2.0 mm (based on which type of effect you're using) result in nominal tactor inflation.
    • These values may change if you modify Body Parameters or Tactor Parameters .
      Note
      If the sum total of all tactor inflation heights exceeds hardware capabilities, we have a filter in place that will compress the inflation signal back into the functional domain. You may configure this behavior with ContactInterpreter::setCompressionFilterAttackRatio and ContactInterpreter::setCompressionFilterReleaseRatio .
  • Make sure that your effects aren't outputting negative values unless you intend to subtract from pre-existing inflation contributions.
  • Make sure that your effect is running (HapticEffect::start , HapticEffect::isRunning ). Also make sure your effect has a reasonable duration (HapticEffect::setDurationS , HapticEffect::setLooping ). It may be the case that it finishes too quickly to be felt.
  • Make sure that your Haptic Effect isn't getting destroyed.
    • Haptic Effects will stop running if they get destroyed by any means (falling out of scope, garbage collection, etc.).

My Haptic Effect is too intense

  • Make sure that your effect is outputting nominal forces or displacements.
    • When working with default values, Haptic Effects that output forces of 100–250 N or displacements of about 0.75–2.0 mm (based on which type of effect you're using) result in nominal tactor inflation.
    • These values may change if you modify Body Parameters or Tactor Parameters .
  • If you have multiple Haptic Effects operating on the same tactor, their results will be summed.

I feel my Haptic Effect everywhere

  • If you are using a SpatialEffect with its bounding volume set to nullptr, this is expected behavior.
    • Define a bounding volume if you want to control where this effect applies spatially.

I always feel my Haptic Effect

  • Make sure your effect has a non-negative duration (HapticEffect::getDurationS , HapticEffect::setDurationS ). All durations less than zero are treated as infinite.
  • Make sure your effect is not set to loop (HapticEffect::isLooping , HapticEffect::setLooping ). If a Haptic Effect is set to loop, it will restart whenever it has been running for longer than its duration.
