Unreal Multi-User Guide

Developing a multi-user project with the HaptX Unreal plugin.

The HaptX Unreal plugin supports collaborative interaction between multiple individuals wearing HaptX Gloves G1. Users can interact with each other and objects in virtual environments from separate physical locations in the real world. This guide covers how to set up and run a multi-user project, and assumes you've already completed the Unreal Integration Guide and are generally familiar with the HaptX Unreal plugin (see Unreal Quick Start Guide).

What the Plugin Will/Won't Synchronize

The plugin will synchronize:

  • HMD location (see HaptxPawn Blueprint)
  • Hand appearance, size, physics state, and pose (see HaptxHand Blueprint)
  • The physics states of objects overlapping the PhysicsAuthorityZone components of HaptxHand Blueprints

The plugin won't synchronize:

  • Game state (non-physical object positions, blueprint variables, etc.).
    • You'll need to implement this yourself.
    • The HaptX plugin utilizes nominal Unreal networking features, so you can do the same (see Unreal Networking and Multiplayer )
  • Objects that don't trigger overlap events with the PhysicsAuthorityZone components of HaptxHand Blueprints*
  • Objects that aren't overlapping the PhysicsAuthorityZone components of HaptxHand Blueprints*

*Unreal has a built-in feature that can synchronize objects that aren't currently interacting with hands. See SetReplicateMovement . The HaptX Unreal plugin works alongside this system so feel free to use it.

Running a Multi-User Project

Note
It is impossible to use two VR headsets on the same workstation so you will not be able to test multi-user interactions with just a single workstation.

By default, multi-user projects built in Unreal must be started from the command line. Use the following commands to execute a packaged build in a multi-user context:

Type Description Command
Listen Server A server that is also a client/player {ProjectName}.exe {MapName}?Listen -game -log
Dedicated Server A server without a client/player {ProjectName}.exe {MapName} -server -log
Client A client/player that connects to a server {ProjectName}.exe {ServerIP} -game -log

See Unreal Client-Server Model for commands that can utilize the editor instead.

How Many Participants Can I Have?

It is computationally expensive to execute the physics simulation at the fidelity required for high-quality haptics, and adding more participants adds many more simulating physical bodies.

In testing, it was found that on PCs that meet the recommended specifications, up to three participants can interact in a multi-user capacity and still experience high-quality haptics. This number is ultimately based on CPU time, and will vary based on the power of the workstations and the complexity of the project itself.

Physics Authority Mode

Latency is a fundamental issue for multi-user projects, and we found that there are significant consequences for multi-user vs. single-user scenarios, depending on how latency is optimized.

To that end, the plugin supports multiple multi-user modes that the developer can select from based on the needs of their project. We call these modes Physics Authority Modes, and which one a project uses can be configured via the Physics Authority Mode property of HaptxCore Blueprint. It can also be set at runtime via AHxCoreActor::setPhysicsAuthorityMode.

See EPhysicsAuthorityMode for detailed descriptions of the available modes.
