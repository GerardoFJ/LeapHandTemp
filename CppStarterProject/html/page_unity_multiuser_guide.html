Unity Multi-User Guide

Developing a multi-user project with the HaptX Unity plugin.

The HaptX Unity plugin supports collaborative interaction between multiple individuals wearing HaptX Gloves G1. Players can interact with each other and objects in virtual environments from separate physical locations in the real world. This guide covers how to set up and run a multi-user project, and assumes you've already completed the Unity Integration Guide and are generally familiar with the HaptX Unity plugin (see Unity Quick Start Guide).

Mirror

The HaptX Unity plugin multi-user implementation is based on Mirror , which is a community-driven continuation of the historical Unity multi-user feature set.

What the Plugin Will/Won't Synchronize

The plugin will synchronize:

  • HMD location (see HaptxPlayer Prefab)
  • Hand appearance, size, physics state and pose (see HaptxHand Prefab)
  • The physics state of objects overlapping the physics-authority zones spawned by an HaptxHand Prefab.

The plugin won't synchronize:

  • Game state (non-physical object positions, script variables, etc.).
    • You'll need to implement this yourself.
    • The HaptX plugin utilizes nominal Mirror networking features, so you can do the same (see Mirror Getting Started )

Running a Multi-User Project

Note
It is impossible to use two VR headsets on the same workstation so you will not be able to test multi-user interactions with just a single workstation.

These steps, performed after the steps described in Unity Integration Guide, will allow you to run multi-user projects in Unity. If you started with the UnityStarterProject, you may skip to step 5.

  1. Delete the HxSinglePlayer component you created.
  2. Add a NetworkManager component and assign your HaptxPlayer prefab variant to its Player Prefab field.
  3. Add a NetworkManagerHUD component to the same game object.
  4. Add HxNetworkRigidbody components to objects whose physics states you want synchronized while not being interacted with by any hands.
  5. Either package or copy your project to a second workstation (version control software is convenient here).
  6. Choose which workstation is going to be the server and press Play on that workstation.
  7. Select LAN Host if the server workstation is also a participant, or LAN Server Only if it isn't.
  8. On your other workstation, type the IP address of the server into the LAN Client text box, then click LAN Client .

How Many Participants Can I Have?

It is computationally expensive to execute the physics simulation at the fidelity required for high-quality haptics, and adding more participants adds many more simulating physical bodies.

In testing, it was found that on PCs that meet the recommended specifications, up to three participants can interact in a multi-user capacity and still experience high-quality haptics. This number is ultimately based on CPU time, and will vary based on the power of the workstations and the complexity of the project itself.

Physics Authority Mode

Latency is a fundamental issue for multi-user projects, and we found that there are significant consequences for multi-user vs. single-user scenarios, depending on how latency is optimized.

To that end, the plugin supports multiple multi-user modes that the developer can select from based on the needs of their project. We call these modes Physics Authority Modes, and which one a project uses can be configured via the Physics Authority Mode property of the HaptxCore Prefab. It can also be set at runtime via HxCore.PhysicsAuthorityMode.

See PhysicsAuthorityMode for detailed descriptions of the available modes.
